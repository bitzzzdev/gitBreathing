# GitBreathing

GitBreathing turns GitLab profile activity into a configurable profile SVG and animated ASCII artwork for profile READMEs.

## What it displays

The profile renderer reads `gitbreathing.json` and the profile data fetched during CI.

- GitLab username, name, bio, pronouns, location, organization and website
- Manually configured social links and ORCID
- Public GitLab projects and their star and fork counts
- Total GitLab activity events and a daily activity heatmap for the last 12 months
- Four independently configured corner motifs
- Standalone animated ASCII artwork in SVG, GIF and PNG formats

The activity panels count GitLab user events returned by the Events API. They are an activity measure, not an official contribution-calendar total. Event types can include pushes, issue and merge request activity, comments and other account events.

GitLab does not expose the same profile fields as GitHub. GitHub-only metrics such as starred repositories, GitHub Projects, pull request review totals and GitHub contribution-calendar data are not shown by this configuration.

## Setup

Requirements:

- Node.js 22 or newer
- A GitLab personal access token with the `api` scope for profile and event reads and generated-file write-back

Install dependencies:

```sh
npm install
```

Set the token in your shell, then build and test:

```sh
export GITLAB_TOKEN=your_gitlab_token
npm run build
npm test
```

Fetch GitLab profile data and render the files:

```sh
CONTRIBUTIONS="$(node scripts/fetch-gitlab-profile.mjs)" npm run render
npm run render:profile
```

Generated files are written to `dist/`.

## CircleCI

The project uses CircleCI with GitLab as the source repository. The configuration is in [`.circleci/config.yml`](.circleci/config.yml).

1. Open the CircleCI project settings for `bitzzdev/gitbreathing`.
2. Add an environment variable named `GITLAB_TOKEN`. Use a GitLab personal access token with the `api` scope.
3. Push changes to the `dev` branch to run the pipeline.
4. CircleCI installs dependencies, runs the TypeScript build and tests, fetches GitLab profile data, renders the assets and commits changed files under `dist/` to `dev`.

Generated asset commits include `[skip ci]` to prevent a second pipeline from starting. Keep the token in CircleCI environment variables. Never put it in `gitbreathing.json` or commit it to the repository.

## Configuration

Edit `gitbreathing.json` to change the username, art styles, contribution scaling, colors, social links, ORCID, profile fields and corner motifs.

The two activity panels can be enabled or disabled independently under `readme.visualizations`:

- `total` controls the total activity number, bar or ring.
- `daily` controls the daily activity heatmap or bar chart.

Each corner accepts an independent motif. Available motifs include `fire`, `titan`, `demon`, `cursed`, `chakra`, `pirate`, `spirit`, `hunter`, `dragon`, `moon`, `vines`, `cave` and `none`.

The anime presets use original geometric motifs inspired by broad genre visual language. They do not include official character art, show logos or copied screenshots.

## Output files

| File | Description |
| --- | --- |
| `dist/profile.svg` | Complete profile composition |
| `dist/slash.svg` | Animated breathing artwork |
| `dist/slash.gif` | Animated raster version |
| `dist/slash.png` | Static first frame |
| `dist/slash.txt` | Plain-text first frame |
| `dist/profile-data.json` | GitLab profile and activity data used for rendering |
| `dist/metadata.json` | Renderer settings and output metadata |

## Privacy

GitBreathing has no hosted backend or telemetry. CI fetches public GitLab profile, project and activity data using the token stored in CircleCI. The generated SVG contains only fields enabled in the configuration. The token is used by the CI job and is not written into generated files.
